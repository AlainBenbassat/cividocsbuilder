Improving the CiviCRM Documentation

We have been looking at how to improve the current CiviCRM documentation during the sprints in Montara (2025), Lunteren (2025), and Paris (2026).

Weakness of The Current Documention

The current documentation can be found at https://docs.civicrm.org/.

The main weakness is that it's not user-centered:

  • The main horizontal navigation is about creating documentation, adding a new book, and the documentation source on gitlab. It does not help users find what they are looking for.
  • The first handbook is about the community policies and conventions. Not what a regular user is looking for.
  • There is no global search. You have to open a guide in order to be able to search in that guide.

Alternative 1: Improved Navigation

Alternative 1 takes the existing documentation but presents it differently.

  • The main horizontal navigation points to the current guides: installation guide, user guide, sysadmin guide, and the developer guide.
  • There is a global search box.
  • There is a welcoming home page inviting the visitor to either browse by type of user, or by content category, or by popularity, or just search.
  • The existing French, Spanish, and Catalan user guides have been integrated by making the site multilingual. A language switch was added to the site header.
  • It hints at the Diátaxis framework for documentation. (not implemented because it is out-of-scope of this alternative)

Alternative 2: Merged Guides + AI

Why have a separate user guide, installation guide, and sysadmin guide? Let's merge them into a single guide!

And why not use AI to apply the Diátaxis framework, make the instructions clearer, have automatic translations...
